# Whole-market wallet discovery and wallet PnL data sources for Solana pump.fun copy-trading (as of 6 Nov 2026)

Scope: Solana only, pump.fun bonding curve (program `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P`) + PumpSwap (`pAMMBay6oceH9fJKBRHGP5D4bD4sWpmSwMn52FMfXEA`). Prices are what the providers' own pages showed on 6 Nov 2026 unless flagged. Several provider doc sites were mid-migration or partially down during research (Birdeye docs → `data.birdeye.so/docs`, many 404s; Flipside docs host dead; `shyft.to/pricing` 404), so a few numbers come from search-engine snippets of the official page rather than a full fetch — those are flagged "(snippet)".

## Key question 1 — Which sources can rank ALL wallets (not a curated list) by realised PnL on pump.fun over 30–90 days, and at what cost per full scan?

### Takeaway
Only three self-serve APIs expose a pre-computed, market-wide wallet leaderboard: SolanaTracker (`/v2/pnl/leaderboard/top`, 1/7/30/90-day windows, capped at the top 500,000 wallets per period), Vybe (`/v4/wallets/top-traders`, 1d/7d/30d only, free tier) and GMGN (unofficial, reverse-engineered `rank/{chain}/wallets/{period}` endpoint). Everything else is either per-token (Birdeye, Moralis, Vybe by-token, Bitquery aggregations), per-wallet (Cielo, Helius, Shyft, Moralis) or do-it-yourself SQL (Dune). Flipside is defunct (see dedicated section).

### Cited Findings

**SolanaTracker Data API (REST; whole-market leaderboard exists)**
- Top-trader board: endpoint `/v2/pnl/leaderboard/top`; `days` accepts 1, 7, 30, or 90 (default 90) as a rolling window; sort fields `realized` (default), `volume`, `days`, `roi`, `win_percentage`, `trades`, `tokens`; "coverage is capped at the top 500,000 wallets per period"; a wallet can trade and still be missing, in which case call `/v2/pnl/wallets/:wallet` directly — [SolanaTracker leaderboards guide](https://docs.solanatracker.io/guides/pnl-v2/leaderboards.md)
- KOL boards (`/v2/pnl/leaderboard/kols`, `/kols/period`, `/kols/calendar`, `/kols/date`) rank only the tracked roster: "KOLs are tracked wallets with a public identity." Platform filters listed: `axiom` (`axiom-flash` alias), `bloom`, `photon`. No pump.fun/PumpSwap statement, no freshness statement, no max `limit` stated (examples use 25 and 50) — [SolanaTracker leaderboards guide](https://docs.solanatracker.io/guides/pnl-v2/leaderboards.md)
- Per-token ranking: `GET /v2/pnl/tokens/{token}/traders` with `sort` ∈ `pnl, realized, unrealized, invested, roi, holding, value, first_trade, last_trade`, `activeOnly`, `minTrades`, `excludeArbitrage` (default true), `excludeZeroBuys` (default true), `platform` filter; `GET /v2/pnl/tokens/{token}/first-buyers` returns traders in chronological order (`sort=first_trade&direction=asc`) and rejects leaderboard-style sorting — [SolanaTracker token intelligence](https://docs.solanatracker.io/guides/pnl-v2/token-intelligence.md)
- Wallet PnL v2: `GET /v2/pnl/wallets/{wallet}` (+ `/positions`, `/tokens/{token}`, `/history`, `/chart`, `/performance`, `/highlights`, `/risk`); `period` ∈ `1d, 7d, 14d, 30d, 90d, all`; `pnlMode` ∈ `strict|adjusted|raw`; positions accept `market=pumpfun`; `performance` `days` default 30, max 365; chart "returns up to 180 daily data points" — [SolanaTracker wallet analysis](https://docs.solanatracker.io/guides/pnl-v2/wallet-analysis.md)
- Pricing (EUR/month): Free €0 = 2,500 requests/month at 3 req/s; Advanced €50 = 200,000; Pro €200 = 1,000,000; Premium €397 = 10,000,000 (+ Datastream); Business €599 = 25,000,000; Enterprise €1,499 = 100,000,000; Enterprise+ custom; annual billing −30%; over quota → 429, no overage billing; Datastream (incl. "PnL V2" rooms) starts at Premium — [SolanaTracker pricing](https://docs.solanatracker.io/pricing.md); the marketing page lists the same tiers and states "No rate limit" for paid plans — [solanatracker.io/data-api](https://www.solanatracker.io/data-api)

**GMGN (unofficial public endpoint; official API is closed-beta/whitelist)**

### Inferences
- A true "rank every pump.fun wallet by realised PnL over 90 days" is available off-the-shelf only from SolanaTracker's `/v2/pnl/leaderboard/top` (`days=90`, sort `realized`), and even that is bounded at the top 500,000 wallets per period. Cost per full scan = (500,000 ÷ page size) requests; with the undocumented page size, a 100-row page implies ~5,000 requests, which fits inside the €50 Advanced tier (200,000 requests/month) and would even fit the free tier's 2,500 requests only if pages are ≥200 rows. Page size and whether the board can be filtered to pump.fun-only trades are unverified.
- Vybe's board is free to call but limited to 30 days and returns ≤1,000 rows per page; 90-day ranking is not possible without re-aggregating `/v4/wallets/{owner}/pnl` (50 credits each) yourself.
- GMGN is the only source that also exposes a copier/follower count (`follow_count`), but only via unofficial scraping; the official API is whitelist-gated and oriented to trading/agent use.
- Birdeye can only approximate a market-wide ranking token-by-token (top traders per token at `90d` sorted by `realized_pnl`) and then union/aggregate wallets; cost scales with number of tokens scanned × per-call CU (CU for top-traders was not retrievable because the reference pages 404). The `/wallet/v2/pnl/*` endpoints then price per-wallet verification at 30–40 CU each.
- Dune is the only option where the ranking logic is fully yours (SQL over `dex_solana.trades`, 3-hour lag), but whether pump.fun bonding-curve fills are in that table under a `project` value could not be confirmed from the docs; expect to need a Plus plan ($399, 25,000 credits) for repeated full-market 90-day aggregations and API extraction (2 credits/MB).
- Bitquery can produce per-token leaderboards and first-buyer lists, but a market-wide 30–90-day wallet ranking would require either many bounded archive queries (add-on from ~$70/mo, every query must be time/slot-bounded, "multi-day ranges can time out") or buying Parquet exports from the Data Store; it is not a practical "one call" ranking source.
- Helius, Shyft, Cielo and Moralis cannot rank the market: they are per-wallet lookups (Helius/Shyft/Moralis) or per-wallet PnL (Cielo), so they serve the verification step after another source has produced candidates.

### Gaps
- SolanaTracker: maximum `limit` per leaderboard page, update frequency, whether the board includes bonding-curve + PumpSwap trades only or all DEXes, and how "top 500,000" is selected are not documented.
- Vybe: credit cost of `/v4/wallets/top-traders` and total page count are not documented.
- Birdeye: current tier table could not be fetched in full (garbled/404); Starter CU allowance conflicts (3M in page snippet vs 8M in the brief); gainers-losers endpoint docs 404.
- Dune: no primary source confirms pump.fun/PumpSwap `project` values in `dex_solana.trades` or the existence/naming of decoded `pumpdotfun_solana` tables; needs an in-editor `SELECT DISTINCT project` check.
- GMGN: no official public leaderboard spec, rate limits or pricing could be found; the known path is reverse-engineered and may break.
- No source was found that exposes "how many copiers follow this wallet" other than GMGN's scraped `follow_count`; Padre/Axiom/Kolscan have no public API for it.

## Key question 2 — Which sources give per-trade timestamps/slots precise enough to measure entry position within a slot relative to another wallet?

### Takeaway
Slot + transaction index (the two fields needed to order two wallets inside one slot) are exposed by Helius `getTransactionsForAddress` (`slot`, `transactionIndex`), Bitquery (`Block_Slot`, `Transaction_Index` in filters/order; signer and index returned in bundle-check queries), and Moralis Solana swaps (`blockNumber`, `transactionIndex`). SolanaTracker, Vybe and Cielo expose millisecond or block timestamps only, which cannot resolve intra-slot ordering.

### Cited Findings
- Helius: each returned transaction includes `slot`, `blockTime` (may be null) and `transactionIndex`; pagination token format is "slot:position"; filters on `slot` and `blockTime` — [Helius getTransactionsForAddress](https://www.helius.dev/docs/rpc/gettransactionsforaddress)
- Bitquery: `Block_Slot` appears in `orderBy` and filters; `Transaction_Index` appears in `orderBy`; bundle-check queries filter `Block: {Slot: {eq: ...}}` and return `Transaction { Index Signer FeePayer }`; archive guidance says "Order by slot, not time" — [Bitquery Pump.fun API docs](https://docs.bitquery.io/docs/examples/Solana/Pump-Fun-API/); [Bitquery individual-trades history](https://docs.bitquery.io/docs/API-Blog/solana-individual-trades-history-api/)
- Moralis Solana swaps: per swap `transactionIndex`, `blockNumber`, `blockTimestamp` (example `2024-11-21T09:22:28.000Z`); no `slot` field name (on Solana `blockNumber` is the slot) — [Moralis get-swaps-by-wallet-address](https://docs.moralis.com/web3-data-api/solana/reference/get-swaps-by-wallet-address)
- SolanaTracker wallet trades: per trade `tx`, `from`, `to`, `price`, `volume`, `wallet`, `program`, `time` (integer, example `1742287684000`); "`slot`: not in the schema" — [SolanaTracker get-wallet-trades](https://docs.solanatracker.io/data-api/wallet/get-wallet-trades.md); first-buyer rows carry `timing.firstTrade`/`timing.lastTrade` (13-digit values, i.e. ms) and no slot or position index — [SolanaTracker token intelligence](https://docs.solanatracker.io/guides/pnl-v2/token-intelligence.md)
- Vybe wallet PnL per token exposes `latestTradeBlocktime` and buy/sell "latest trade fields"; no slot in the documented schema — [Vybe wallet PnL reference](https://docs.vybenetwork.com/reference/get_wallet_pnl_v4)
- Cielo: `last_trade_timestamp` (Unix) on positions/trading-stats; "The schema has no explicit first-buy timestamp field" on positions; `token_age` on token PnL rows — [Cielo Wallet PnL & Stats](https://docs.cielo.finance/api-reference/wallet-pnl-and-stats.md)
- Dune `dex_solana.trades` overview names only `block_time`, `amount_usd` and `project` columns; the full column list page 404'd — [Dune Solana DEX trades overview](https://docs.dune.com/data-catalog/curated/dex-trades/solana/overview)
- Shyft `getTransactionsForAddress` returns "signatures and transaction data in a single call" but only for 3–4 days of history — [Shyft pricing](https://shyft.to/solana-rpc-grpc-pricing); [Shyft code examples](https://docs.shyft.to/solana/get-transactions-for-address/code-examples.md)
